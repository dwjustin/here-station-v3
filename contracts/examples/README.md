# 경로 응답 예시

`route.json`은 요청이 성공했을 때 반환할 데이터의 초안이다. API 요청 본문이나 전체 지도 파일은 아니다. Python과 TypeScript에서 같은 파일을 읽어 함수 연결과 화면을 개발할 수 있다. 서버의 `POST /routes`에서 이 파일을 반환하며 모바일 연결 코드는 아직 포함하지 않는다.

## 데이터 출처와 한계

- 출발: 일원역 1번 출구, 원본 POI ID `exit2`.
- 도착: 학여울역 1번 출구, 원본 POI ID `exit5`.
- 각 노드의 POI ID, 이름, 종류, 층, 좌표, 출구 번호는 제공된 `ilwon.json`, `hakyeoul.json`에서 가져왔다. ID의 숫자를 출구 번호로 해석하지 않는다.
- **방문 순서와 모든 엣지는 mock**이다. A*를 실행하거나 실제 보행 가능성, 계단 연결, 개찰구 통과, 승강장 운행 방향을 검증하지 않았다. 층이 달라지는 예시 연결은 `stairs`로 표시했으며 원본 계단의 실제 연결을 보장하지 않는다. 실제 길안내에는 사용하지 않는다.
- 원본은 보행 격자를 Base64로 압축한 `nodes.cell`, `nodes.h`와 POI를 담고 있다. 명시적인 보행 엣지나 철도망은 없다. 실제 경로는 격자 디코딩, 높이·층을 고려한 인접 관계, 계단·엘리베이터 연결, POI 연결 처리가 필요하다.
- 역 사이 `rail` 엣지는 UI 개발용 연결이다. 중간 정차역·운행 방향·시간표는 제공된 지도에서 알 수 없으므로 생략했다. 실구현에는 별도의 철도망 정보가 필요하다.
- 거리·시간·최적 여부는 계산하지 않았으므로 응답에 넣지 않았다. 대용량 원본 파일은 레포에 복사하지 않았다.

## 형식

| 필드 | 의미 |
| --- | --- |
| `schema_version` | 응답 형식 초안 버전. 지도 데이터 버전과 별개 |
| `is_mock` | 실제 길찾기 결과가 아닌 예시임을 표시 |
| `coordinate_system` | 미터 단위의 역별 로컬 좌표. `x`는 동쪽, `z`는 남쪽, `h`는 역 원점 기준 높이 |
| `maps` | 역별 원본 파일명, 내용 SHA-256, 원점 위경도. 해시는 이번 파일을 식별하기 위한 것으로 정식 지도 배포 버전 체계는 미정 |
| `origin_node_id`, `destination_node_id` | 출발·도착 노드 참조 |
| `nodes` | 실제 방문 순서의 배열. 이번 예시는 원본 POI를 경로 노드로 사용 |
| `nodes[].id` | 응답 안에서 유일한 ID. 이번 예시는 `역 ID:POI ID` 형태 |
| `nodes[].station_id` | 좌표가 속한 역과 `maps` 항목을 식별 |
| `nodes[].poi_id` | 원본 지도 POI 참조. 향후 일반 보행 지점은 POI가 아닐 수 있으므로 이 필드는 선택값으로 확장 가능 |
| `nodes[].position` | 원본 POI의 `x`, `z`, `h` 값. 격자의 행 수인 최상위 `h`와 구분 |
| `edges` | `nodes[i]`와 `nodes[i+1]`을 연결하는 순서 있는 배열. 개수는 노드 수보다 하나 적음 |
| `edges[].kind` | `walk`, `stairs`, `rail`. 실제 구현에서 필요한 이동 유형을 추가할 수 있음 |
| `edges[].instruction` | 목록에 표시할 예시 안내 문구. 실제 안내 판정은 `kind`와 노드 데이터를 사용 |

## 프론트와 위치 추정 연결

목록에서는 출발 노드, 첫 엣지, 다음 노드 순서로 번갈아 표시한다. 엣지의 `instruction`을 이동 설명으로 사용한다.

길안내는 현재 엣지와 그 엣지의 `to_node_id`를 다음 목표로 사용한다. `walk` 구간은 현재 위치에서 다음 노드로 향하는 방위각과 현재 기기 방향의 차이로 화살표를 그릴 수 있다. `x=동`, `z=남`이고 북쪽을 0도로 하는 시계 방향 방위각이라면 목표 방위각은 `atan2(target.x - current.x, -(target.z - current.z))`를 도로 변환하고 0~360도로 정규화한 값이다. 기기 방향도 같은 북쪽 기준이어야 한다.

이 예시의 노드들은 POI 체크포인트뿐이다. 체크포인트 사이를 직선으로 안내하면 벽을 통과할 수 있으므로 화살표 시연에만 사용한다. 실제 구현은 알고리즘이 반환한 보행 경로의 굴곡 지점을 중간 노드로 넣어야 한다. 위치 추정 결과도 같은 역·지도 좌표계로 변환해야 한다.

`stairs` 구간은 층 이동 안내를 표시하고 층 이동 완료 여부로 진행한다. `rail` 구간에서는 나침반 화살표를 중단하고 열차 이동 안내를 표시한다. 서로 다른 역의 로컬 좌표를 빼서 거리나 방향을 계산하지 않는다. 열차 이동 완료는 위치 추정 또는 사용자 확인으로 판단할 연결 지점이며, 이 파일에는 자동 판정 로직이 없다.

현재 엣지 인덱스, 기기 방향, 위치 추적 상태는 모바일 실행 상태이므로 이 응답에는 넣지 않는다. 노드 도달 반경과 층 이동 판정 기준도 위치 추정 팀과 구현하면서 정한다.

## 변경 방법

이 형식은 실행 가능한 합의를 시작하기 위한 초안이다. 함수 구현 중 입력·출력이 바뀌면 이 예시와 설명, 이후 작성할 Pydantic 모델·TypeScript 타입·호출부를 함께 수정한다. 호환성을 예상한 범용 변환 계층은 미리 만들지 않는다.
